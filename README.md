**현재 실행 단계는 Instagram 성장과 고추장 구매 전환입니다.** 첫 상품 중심 12초 릴스와 표지·캡션을 제작했으며 아직 게시되지 않았습니다. 사용자의 10/25 지시에 따라 chat.kmingo.com·app.kmingo.com 홍보와 가입 실험은 **QA에 이상이 없음을 확인하고 사용자가 다시 진행을 승인할 때까지 보류**합니다. 두 서비스의 장기 회원 성장 목표와 이미 승인된 공개 프로필은 유지합니다.

**구매 경로는 [우체국쇼핑 KMINGO 상품 페이지](https://sijang.epost.go.kr/fo/goods/goodsDetailView.do?goodsCd=EA2008119&pavlnDivCd=02)이며, [kmingo.com](https://kmingo.com)은 브랜드 홈페이지입니다.** 10/25 상품 페이지에서 “KMINGO 프리미엄 고추장 오리지널450g” 판매가 **27,000원**, 기본 배송비 **3,000원**(100,000원 이상 무료배송), 공급업체 (주)플라밍고를 확인했습니다. 결제를 실행한 것은 아니며, 주문 시 최종 조건과 해외 배송 가능 여부는 별도 확인합니다. 첫 릴스의 가격·구매 안내를 이 기준으로 정정해 최종 영상 파일을 다시 제작했습니다. 제작을 조회·구매 실적으로 집계하지 않습니다.

현재 CLI가 자동 집계하는 것은 운영자가 입력한 활동·피드백·결제 원장입니다. Instagram 인사이트, 두 서비스의 가입 기록, 주문 배송 국가의 자동 수집·분류는 아직 구현되지 않았습니다. 이들 지표는 확인 전 **미측정**으로 두며, 이 문서의 목표 추가를 연동 완료나 실제 성장으로 표시하지 않습니다.

## 바로 실행

Node.js 24 이상이 필요합니다. 외부 패키지 설치 없이 실행합니다.

~~~sh
npm run daily
npm run report
npm run status
~~~

daily는 루프를 한 번 실행하고 한국 시간 기준의 개인 일지와 공개 집계 파일 daily/YYYY-MM-DD.md를 만듭니다. loop는 타깃·문구만 갱신합니다. 새 근거가 없으면 전략과 문구를 유지합니다.

~~~sh
npm run feedback -- --file input/feedback.json
npm run loop
npm run activity -- --file input/activity.json
npm run order -- --file input/order.json
npm run daily -- --note-file input/operator-note.txt
~~~

피드백을 실제 사실로 처리한 뒤 제안을 전달하고 활동을 기록합니다. 결제는 실제 결제 관리 화면에서 확인한 뒤 입력합니다. [테스트용 입력 템플릿](examples/)은 isTest:true 또는 미결제 상태로 제공하며 실제 실적으로 계산하지 않습니다.

## 반복하는 일

**기존 기록 → 실제 반응·결제 확인 → 타깃 재선정·문구 가설 → 사람의 검토·전달 → 성과·개선 이유 기록 → 다음 회차**

1. 출처와 기존 판단을 읽습니다.
2. 직접 받은 피드백을 기록합니다.
3. 루프를 실행합니다.
4. 대상별 이전/이후 제안과 이유를 검토합니다.
5. 실제 다음 반응이 생기면 같은 과정을 반복합니다.

실행 상태와 개인별 원장·이전 일지 수정본은 Git에서 제외하는 data/state.json에 남습니다. 공개 일지에는 집계와 코드로 정한 개선 이유만 담습니다. 예약 실행 환경과 수동 재실행 방법은 OPERATIONS.md를 따릅니다.

## 실제 피드백 입력

실제로 받은 피드백을 UTF-8 JSON 파일로 작성합니다. 파일 위치를 input/feedback.json으로 정한 경우 다음 명령을 실행합니다.

~~~sh
npm run feedback -- --file input/feedback.json
npm run loop
~~~

파일 형식:

~~~json
{
  "leadId": "Q01",
  "text": "실제로 받은 피드백 원문으로 바꾸세요",
  "sourceKind": "peer",
  "facts": {}
}
~~~

형식 예시를 실제 반응으로 저장하지 마세요. sourceKind는 customer(직접 고객 응답), partner(직접 파트너 응답), peer(동료 검토), public(공개 자료) 중 실제 출처를 선택합니다. 확인된 사실만 facts에 넣습니다.

지원하는 사실은 jarStatus(unknown/full/low/none), purchaseIntent(unknown/yes/no), country, deliveryEligible(unknown/yes/no), dish, timeBudgetMinutes, objection(none/time/price/heat/ingredients), stopContact(true/false)입니다. 배송 가능은 국가만 보고 추정하지 않고 직접 확인합니다. eventId로 같은 피드백의 중복 입력을 막으며 isTest:true 피드백은 실제 지표·학습에서 제외합니다.

동료·공개 의견은 제안 검토에 반영하지만 해당 고객의 보유량·국가·구매 의사를 바꾸지 않습니다.

서로 다른 실제 응답자 2명 이상에게 같은 가격·시간·맵기·원재료 우려가 확인되면 다음 우선 타깃의 문구 가설을 바꿉니다. 다른 고객의 사실을 덮어쓰지 않으며, 소규모 반응만으로 구매 전환의 승자를 선언하지 않습니다. 이미 확인한 국가·요리·시간은 반복 질문하지 않습니다.

## 새 기회 추가와 내보내기

~~~sh
npm run add -- --file input/new-lead.json
npm run export -- --output exports/state.json
~~~

새 후보 JSON에는 name, type(consumer/partner), sourceUrl, evidence가 필요합니다. 같은 출처는 중복 추가하지 않습니다. 내보내기에는 저장소 안의 새 JSON 경로를 지정합니다.

## AI와 함께 운영

[ROUTINE.md](ROUTINE.md)를 Codex 또는 Clone에 읽히면 기존 기록을 검토하고 다음 실험을 준비하는 운영 지침으로 사용할 수 있습니다.

- 기본 규칙 모드는 별도 API 키 없이 동작합니다.
- npm run loop -- --ai는 OpenAI Responses API로 다음 행동에 맞는 문구와 질문을 생성합니다. 모델이 고객 사실·성과 지표·연락 중단 상태를 바꾸지는 않습니다.

현재 제공본은 **규칙 모드 검증 완료, 실제 OpenAI 호출 미검증**입니다. 키의 로컬 저장이 완료되지 않았고 추가 생성은 보류했습니다. API 키가 없거나 호출이 실패하면 AI 성공으로 표시하지 않습니다.

API 설정은 Git에서 제외되는 .env.local에서 읽습니다. 키를 코드·브라우저·GitHub에 넣지 마세요. 설정 항목은 .env.example, API 계약은 [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)와 [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)를 참고합니다.

## 지표와 출처

처음 들어 있는 것은 공개 자료 10개입니다. 실제 활동·응답·주문 원장은 비어 있습니다. 주문 목표 달성은 원장의 기간·증빙·귀속·상태 조건으로 계산합니다.

- 과거 게시물 댓글은 우리 제안에 대한 응답으로 세지 않습니다.
- 직접 고객 응답, 파트너 응답, 동료 검토를 구분합니다.
- 클릭·문의·구매 의사를 주문으로 계산하지 않습니다.
- 이 루틴은 이메일·댓글·DM을 발송하거나 결제를 처리하지 않습니다. 실제 완료한 제안·유입과 확인 결제만 별도 입력합니다.
- 같은 주문은 한 번만 집계하고, 취소·환불·테스트·증빙 미확인·기간 외 주문은 제외합니다. 변경 전 상태를 원장 이력에 보존합니다.
- 같은 제안에서 주문이 여러 건 발생해도 전환율의 분자는 한 번만 셉니다. 주문 수와 고유 구매자 수는 따로 보여줍니다.
- 제품 라벨·맵기·재고·배송 조건이 미확인인 경우 그대로 남깁니다.
- Q03은 검색 보관본을 읽었고 직접 페이지 재열기는 실패했습니다.
- 클래스 운영자의 공개 프로그램은 협업 의향을 뜻하지 않습니다.

각 원문 링크와 검증 범위는 seed.json에 있습니다. 실행 데이터·입력 피드백·내보내기·비밀키는 Git에서 제외합니다.
